# ToneCustoms — Customer Updates & Notifications

**One place to understand where ToneCustoms news, support replies and product changes appear.**

## What you can follow

| Update | Official location | How to follow |
| --- | --- | --- |
| Support ticket replies, assignments and status changes | [GitHub Support Issues](https://github.com/ToneCustoms/tonecustoms-docs/issues) | Open your issue and select **Subscribe** in GitHub Notifications |
| Confirmed script releases, bug fixes and version histories | [Script Updates](SCRIPT_UPDATES.md) | Check the update hub and product changelog; watch the repository if you want GitHub activity alerts |
| New features, demonstrations and development status | [Script Features](FEATURES.md) | Visit the feature directory and [Developer Insights](INSIGHTS.md) |
| Official announcements and support notices | [Announcements](ANNOUNCEMENTS.md) | Follow announcements on the website or watch the GitHub repository |
| Community discussion | [ToneCustoms Discord](https://discord.gg/JdZ7NTG5KF) | Choose your Discord notification settings |
| Order, billing and private purchase questions | Your original private Tebex order-support thread | Follow your Tebex order correspondence |

## What happens when you open a support ticket?

1. GitHub Actions acknowledges your public request and categorizes it.
2. A verified assigned handler is identified in an ownership comment; unknown assignees are **not** presented as official staff.
3. The ticket status indicates New, Investigating, Waiting on Customer or Resolved.
4. Subscribe to the issue to follow responses. You can unsubscribe or customize GitHub notification settings.
5. If your ticket requires private payment or order information, move that discussion to the private Tebex channel.

**Important:** ToneCustoms can publish GitHub comments and status changes, but **GitHub determines whether and how email, push or inbox notifications are delivered**. We do not promise automatic email alerts for every documentation edit, script update or feature preview.

## Script update publishing rules

An update is customer-facing only when the actual release is confirmed. Every released update should identify the script, version, date, added features, fixes, compatibility changes and upgrade steps. A showcase video, private commit or in-development concept is not a release.
